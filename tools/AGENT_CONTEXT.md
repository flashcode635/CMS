# Directory: tools

Primary Purpose: Developer/agent tooling that is **not** part of the Next.js bundle or the runtime. Today that is one shell script, `search.sh`, wired to `npm run find`. The `npm run graph` / `npm run graph:check` commands that `AGENTS.md` describes are declared in `package.json` but their implementation file is missing, so repo-graph generation and staleness checks do not work in this checkout.

> Dependencies/Consumers/Runtime lines are normally regenerated by `npm run graph`. That script is missing (see "Missing tooling" below), so this file is maintained by hand.

## Files

### `search.sh`

[search.sh]: Bash file-name search for the project: case-insensitive `find` over the repo excluding build/dependency dirs, with the query highlighted in the results and a match count. Exposed as `npm run find [query...]`.

- **Runtime:** local developer shell (bash). Not bundled, not imported by any TS/JS file.
- **Purpose:** Fast "where is the file named …" lookup for agents and humans, without dragging `node_modules`, `.next`, `.git`, build output or coverage into the results. It searches **file names only**, not file contents.
- **Exports & signatures:** None in the module sense. Interface:
  ```bash
  npm run find <query>          # → bash tools/search.sh <query>
  npm run find                  # → prompts: "Search file name: "
  bash tools/search.sh Button   # same, without npm
  ```
  - Query = **all** arguments joined: `QUERY="$*"` (spaces are preserved as one substring; there is no `-name`/`-path` mode, no regex mode, no `--help`).
  - `package.json`: `"find": "bash tools/search.sh"` — arguments after `--` or directly are forwarded by npm.
- **Internals / data flow:**
  1. `ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"` then `cd "$ROOT" || exit 1` — always runs from the **project root**, so results are repo-relative no matter where it is invoked from.
  2. Colour constants: `GREEN`, `RED`, `CYAN`, `HL` (bold black on yellow), `RESET`.
  3. No argument → interactive `read -rp "Search file name: " QUERY`. Still empty afterwards → `echo "${RED}Nothing to search.${RESET}" >&2; exit 1`.
  4. Search:
     ```bash
     find . \
       \( -name node_modules -o -name .next -o -name .git -o -name dist -o -name build -o -name out -o -name coverage \) -prune \
       -o -type f -iname "*${QUERY}*" -print | sed 's|^\./||' | sort
     ```
     Case-insensitive substring match (`-iname "*query*"`), files only (`-type f`), pruned directories: `node_modules`, `.next`, `.git`, `dist`, `build`, `out`, `coverage`. `./` prefix stripped; output sorted.
  5. No matches → `echo "${RED}No files found for '<query>'${RESET}"` and **`exit 0`** (a no-match is not an error).
  6. Highlighting: the query is regex-escaped (`sed -E 's/[][\.*^$/+?(){}|-]/\\&/g'`), then `sed -E "s/${ESC}/${HL}&${RESET}${GREEN}/Ig"` wraps every case-insensitive occurrence (including in directory segments of the path) and a second `sed` adds a leading `GREEN` / trailing `RESET` per line.
  7. Trailer: blank line + `${CYAN}<N> file(s) found${RESET}`, where `N` is `wc -l` of the results (always ≥ 1 here).
- **Constants & types:** Shell variables only: `ROOT`, `GREEN`, `RED`, `CYAN`, `HL`, `RESET`, `QUERY`, `RESULTS`, `ESC`, `COUNT`. Prune list as above. No exported env vars.
- **Error handling / exit codes:** `1` only when no query is supplied (or `cd "$ROOT"` fails); `0` on matches and on zero matches. `find`/`sed` failures are not checked (no `set -euo pipefail` in this script). Paths with newlines would skew the count/lines. Colours are emitted unconditionally — piped/CI output contains ANSI escapes.
- **Dependencies:** `bash`, GNU/BSD `find`, `sed`, `sort`, `wc`. No Node/npm packages. Assumes a Unix-like shell (Linux/macOS/WSL).
- **Consumers:** `package.json` script `find` only. `AGENTS.md`/docs may mention it as the file-lookup helper; no TS/JS imports.
- **Notes:**
  - Content search is **not** supported — use `grep -rn "<pattern>" --include='*.ts' --include='*.tsx' .` for symbols; `npm run find` is for paths.
  - Prune is by exact directory **name at any depth**, so a nested `build/` or `out/` folder (even a source folder legitimately named `out`) will be skipped.
  - Filenames with spaces work (results are printed line-wise, not word-split), but the count is line-based.
  - Extend the prune list rather than adding `-not -path` chains; keep the `ROOT`/`cd` logic so results stay repo-relative.

## Missing tooling (verified)

- `package.json` scripts:
  - `"graph": "node tools/graph.mjs"`
  - `"graph:check": "node tools/graph.mjs --check"`
- `tools/` contains only `search.sh` and this `AGENT_CONTEXT.md` — **`tools/graph.mjs` does not exist**.
- The generated `graph/` directory (`repo-graph.json` / `repo-graph.md`) is **absent** from the repo root.
- Consequences:
  - `npm run graph`, `npm run graph -- --file <path>`, `npm run graph --no-docs` and `npm run graph:check` all fail immediately with Node's `MODULE_NOT_FOUND` (`Cannot find module .../tools/graph.mjs`) and a non-zero exit code.
  - `AGENTS.md`'s "finish every task with `npm run graph:check`" and "read `graph/repo-graph.md`" instructions cannot be satisfied in this checkout; the per-directory `AGENT_CONTEXT.md` files are the only dependency map available.
  - Do **not** treat the absence as permission to invent graph data; update the relevant `AGENT_CONTEXT.md` by hand (descriptions + Dependencies/Consumers lines) and verify importers with `grep`.
  - `AGENTS.md` also mentions `--no-docs` and auto-marked `TODO:` entries — those behaviours are unverified because the implementation is missing.
